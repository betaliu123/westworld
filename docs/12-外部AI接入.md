# 12 · 外部 AI 接入

## 负责什么

所有 LLM 能力（DS flash）的接入方式：前端走服务端代理（serve.py），避免浏览器跨域 + 隐藏 API key。

## 关键文件

- `serve.py` —— 静态服务器 + `/api/llm/chat` 代理
- `.env` —— 配置（LLM_BASE_URL / LLM_API_KEY / LLM_MODEL）
- `npc/NpcChatService.js` —— 单 NPC 自由对话
- `theater/TheaterGlue.js` —— 剧场衔接
- `llm/NarrativeService.js` / `LlmPrompts.js` —— 每日叙事文本
- `factions/StockNewsService.js` —— 股市新闻

## 模型

- `LLM_MODEL=deepseek-v4-flash`（推理模型）
- **flash 必须传 `reasoning_effort`**（none/low/medium/high）；`deepseek-v4-pro` 不传
- 批量内容生成用 `deepseek-v4-pro` 直连（补漏模式 + 逐项校验）

## 服务端代理（serve.py）

`/api/llm/chat` 强制：
- `payload["model"] = LLM_MODEL`
- `max_tokens` 上限（`LLM_MAX_TOKENS`，默认 16000）
- `stream = False`
- 限流：每分钟 N 次（`LLM_PER_MINUTE`）
- 其余参数（reasoning_effort 等）原样透传

## 前端调用模式

统一走 `fetch("/api/llm/chat")`，POST JSON：
```json
{
  "messages": [{"role":"system",...},{"role":"user",...}],
  "temperature": 0.8,
  "max_tokens": 800,
  "reasoning_effort": "low"
}
```

所有调用都有**兜底**：LLM 挂了/超预算 → 退化成模板/关键词，保证玩家永远有回应。

## 各处参数

| 用途 | 文件 | max_tokens | reasoning_effort |
|------|------|-----------|-----------------|
| NPC 自由对话 | NpcChatService `CHAT_GEN` | 6000 | low |
| 剧场衔接 | TheaterGlue `GLUE_GEN` | 12000 | low |
| 股市新闻 | StockNewsService | 800 | low |
| 每日叙事 | NarrativeService | 2000 | （默认） |

## 调试

`Ctrl+Shift+D` → 🤖 实时生成：顶部浮层（Ctrl+L）显示成功/失败/兜底回执、各推理档位切换、LLM 开关。
