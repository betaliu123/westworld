# 岗位饮食与花石纲门路实施计划

目标：依照用户本轮确认，周大石、刻字人守岗用餐；周大石先拒招，玩家以金钱、臂力或女装魅惑争取名额，再换装随队入城。周大石、符祥与货车到镇公所附近；车货可偷，真实证据触发重罚与门路关闭。

采用 config-writing-plans 与 config-subagent-driven-development；本项目为 JavaScript 世界规则与 Three.js 场景，没有外部配置表或 Unity 资产。用户已明确授权功能方案。保留其他进行中的改动，不发布、不覆盖玩家存档。

- [ ] 固定岗位：以岗位策略决定饮食目标，周大石和刻字人使用真实随身干粮；不凭空吃饭，不去公共食摊，危险仍可中断。一次初始化兼容存档；昼夜与进城后的岗位统一。
- [ ] 招工：首次问缺人得到拒绝；同轮最多三种回应。贿赂暂定六文；臂力、魅惑用预览同源的真实检定，魅惑检查穿戴女装而非主角性别。成功只给一次同意与短褂；失败可换其他办法。已有挑夫装束仍可直接提出入队，不依赖先问话。旧档已借衣视为已获同意。
- [ ] 搬石表现：现场石块、靠近、俯身抬起、落地；在动作过程中检定，完成才结算；中断无奖励。服装与物品的表现不能替代实际穿戴事实。
- [ ] 车队：周大石、符祥随车进入镇公所附近，位置与交互、碰撞、货物一致；危险与倒地中断；读档不中断或复制货物。
- [ ] 偷货：真实车上物品、位置、距离与遮挡校验，统一检定反馈；无人目击不自动指认玩家。有人看见或实际发现失窃后留下记录；被认定的行为者承担严重后果，车队拒绝其入队。不能靠贿赂、穿脱洗掉已知行为。
- [ ] 相关对白、事件牌、设计文档同步；回归先问后办、先换装后问、读档继续、重复奖励、出入后返回、偷窃成功/失败与有人/无人目击、两性及女装资格。
- [ ] 独立试玩存档验证新选项与场景；1280×850、1024×768、800×600 检查交谈/检定/物品界面及浏览器错误，保留实现边界。
