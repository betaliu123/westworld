## 2. 当前问题是链路断裂

- src/simulation.js 的 isPursuing 在 gate 事件下直接返回 false；attack 在入城阶段只特殊处理 gate_guard，其他 NPC 的通用受击被提前返回。
- src/ecosystem.js 的 damage 直接按 owner 扣关系、加 wanted，没有统一的目击归属；门、河栅在 world.js 中没有治安管辖元数据。
- world.js 给入城人物单独固定站位与手势；剧情阶段、追击、逃跑、对白、生态姿态分别竞争人物控制，没有统一中断与恢复。
- 目前有情绪、追击、记忆字符串和受击表现，并非完全没有 NPC 逻辑；缺的是它们之间可靠的接口。

不能只取消 gate 的 early return：开场已有三星嫌疑，直接套“通缉即追击”会导致守卫未认出玩家就开打。必须先分开真实世界、NPC 知识和当前意图。

## 3. 共同架构

世界行为 → 事件事实 → 各 NPC 感知 → 个体知识 → 职责与风险判断 → 抢占日程 → 场景动作 → 后果、传播、恢复。

### 世界事实和人物知识分开

世界事件只记录实际发生的事：eventId、发生时间、地点、actorId、targetId、动作类型、损伤、声音强度、对象归属、管辖区。世界知道 actorId，不等于每个 NPC 都知道。

每个观察者另存：seen/heard/reported/discovered、识别到的主体（可为空）、最后确认位置、时间、证据来源、置信等级。听见砍木声只能知道位置和声音类型；看到破门只能知道破坏结果；看见玩家持刀击中门才可直接归责。口头报告保留报告人，不能自动升级成亲眼目击。

感知用距离、朝向、遮挡与事件显著性。听觉先让人转头/寻找，再用视线确认；不能听见后穿墙锁定玩家。近处挨打可立即确认袭击者。后台减少更新频率不能导致附近守卫漏掉攻击事件。

身份区分“眼前这个人”“衣着描述”“假名”“已确认本人”。现场目击后脱衣不能洗掉当场身份；脱离目击后的换装可降低再识别机会。开场通缉是已有案件压力，不是全 NPC 当前目标锁定。

### 人物档案与物品职责

每人配置职业、所属势力、管辖区、负责物品、勇气、履职倾向、关系、战斗实力、知识。守卫可同时是任务角色，任务不得关闭其感知。

城门/河栅：ownerFaction=官府，jurisdiction=临溪关；当班守卫有 protectArea 职责。商人负责货物；补衣人是差役服的保管人，不因其台词涉及出售就自动知晓所有失窃。

同一件事产生不同选择：守卫制止与拘捕；商人护财、撤退或报官；胆小街坊拉开距离；有侠义倾向的强者先护住受威胁者。第一版不用“所有人都勇敢执法”的统一反应。

### 决策与执行分开

第一版采用有限状态与优先级，不复制大型行为树编辑器，也不让大模型逐帧决定移动。

通用状态：日常、留意、调查、制止、交涉、战斗、逃跑、报告、搜寻、善后。拘捕是守卫可用的职责动作，不是每个村民都能调用的状态。

优先级建议：死亡/昏迷与身体约束 > 受击、自救、近身威胁 > 执法和保护职责 > 有因果期限的任务动作 > 普通交谈 > 日程。火灾中的任务对白不能让人站着不动；日常吐槽不能抢断投降。相同事件去重并设置承诺时间，避免来回切换状态。

每个行动具有前置、目标、接近、执行、完成、失败、取消与恢复；同一 NPC 同时只有一个移动/动作控制者。任务只提供目标和约束，不直接永久霸占人物。事件结束后回到岗位或继续有效任务；目标物品已毁则重选工作，不能对空气重复动作。

## 4. 先把“当着守卫砍门”做完整

以下为调参起点，而非天国参数：清楚目击后约 0.2～0.5 秒内转身；第一次普通破坏，立即喝止并接近，在约 3 秒的短窗口内观察玩家是否停手。放火、攻击人或已严重破坏可跳过口头警告。

| 情境 | 守卫实际行动 | 说话及后果 |
|---|---|---|
| 只听见背后砍击 | 停下当前动作，转头看向声源 | “谁在那边？”；不立刻认定玩家 |
| 清楚看到第一刀砍门 | 转向、抬手制止、走向玩家与门之间的可达位置 | “住手！城门也敢砍？”；记录一次破坏事件 |
| 玩家收刀停手 | 保持戒备，近距离要求解释/赔偿 | 允许当面回应，成功也不会把破门恢复 |
| 玩家继续挥刀 | 拔械、招呼同伴、试图阻止继续破坏 | 拒止升级，不无限重复第一句警告 |
| 玩家直接袭击守卫 | 立即防御、交战 | 不再先走三秒警告流程 |
| 玩家逃走 | 在职责允许范围内追赶 | 只追最后已知位置；丢失视线后局部搜索 |
| 搜寻无果 | 返回岗位，留下修理/报案与外貌线索 | 不隔墙追踪当前位置，不全城瞬间同步 |
| 玩家投降 | 近距离拘捕、解除攻击状态，进入既有牢狱路线 | 押解不可远程瞬移抓人；原事件只结算一次 |

说话是动作反馈，不是动作的替代。警告用头顶短句与朝向、手势；玩家仍可行动。只有玩家靠近并主动回应才进入专门对话镜头，不要第一刀就弹全屏选项。

交涉保持最多三类：解释/利用可信身份（有冲突时检定）、承担责任/赔偿、拒绝或离开。收刀靠动作，逃走靠移动，反抗靠攻击，不重复塞进菜单。不能“魅力成功就让守卫忘记亲眼看见的砍门”；成功可影响处罚轻重、是否接受赔偿或是否升级。

同一段连续破坏合并成一个事件：严重性随损伤和拒止行为升级，不每一刀加一星。个人态度、当地警觉、已确认案件、势力评价分别更新。对未识别者可提升地区警觉，但不得直接把案件归给玩家。

## 5. 自由路线仍然成立

河道破坏产生声音、损伤和碎片，但远处守卫不能因此全知。

- 没人听见/看见：仍可破栅、吃粮、涉水进入；稍后巡查可发现缺口，知道有人破坏，不知道是谁。
- 商人听见：先张望；看清后可能去报告。报告需要到达守卫或处于可听见的呼喊距离。
- 守卫近处听见：调查声源；看到持刀者才质问。可以用声东击西制造空隙，但门岗应有守岗责任，不所有守卫同时离岗。
- 脱离视线后入水：守卫在岸边寻找最后位置；不会无条件跳河或穿墙跟随。
- 玩家溺水：根据敌对与职责选岸边喊话、求援、救援或拒绝冒险。第一版只做转向、呼喊与寻找可达岸边，不声称已有救人动作。

统一规则不保证每条路线同样轻松。玩家的优势来自准备、路线、时机、遮挡、角色关系和承担风险；不能把可行路线改回脚本必败。

## 6. 日常、记忆和 AI

每名示范 NPC 先做 2～3 段可中断日程：守卫守岗/巡查/交接；商人看货/买饼/整理货物；补衣人缝补/取水/收衣。活动连接到具体对象及站位，包含进入、循环、退出与恢复。这样买饼的背身是活动产生的机会，不是点一次按钮让商人永久背过去。

结构化记忆保留事件、身份把握、证据、情绪影响、地点、时间、到期/解决条件。短时戒备可衰减；当面袭击、已立案破坏不能仅靠警告计时归零。赔偿和服刑关闭案件但不恢复物体、不抹掉历史。保存/读档保留物品损伤、证据、案件、最后位置；恢复后重新验证行动目标，不能重复罚款。

确定性规则负责感知、证据、动作可达性、处罚、伤害和物品。AI 负责符合已知事实和人物立场的台词变体、长期个性倾向与内容创作；只接收该 NPC 知道的事实。实时追击、第一次警告不等网络，用本地动作/台词立即响应；AI 超时沿用本地版本，迟到答复不得改变已完成状态。

第一版表现约定：先用转头、停手、走近、挡路、拔械、退避、呼喊、搜索这些已有或可程序化组合的动作；后续补专门动画。没有动画时也先执行真实移动和状态，不能只换一个文字气泡。

## 7. 工程切分与验收

建议新增模块，不继续把所有分支堆进 world.js：

| 模块 | 职责 | 接现有位置 |
|---|---|---|
| world-events | 将攻击、破坏、失窃、闯入写成可去重事件 | ecosystem.damage、simulation.attack、物品转移 |
| npc-perception | 视野/遮挡/听觉，产生观察者证据 | world 的位置、朝向与碰撞体 |
| npc-brain | 职责、风险、优先级，选择状态 | 替代 gate 全局免反应与单一 wanted 追击 |
| npc-actions | 统一接近、看向、制止、追击、搜索、恢复 | world 移动、动作、对白控制 |
| crime-memory | 证据、案件、身份、传播、存档 | wanted、people.memories、势力评价 |

先做一条纵向完整链：城门/河栅/衣架三个物件，守卫/商人/补衣人三个 NPC。首批事件只需破坏、袭击、偷窃。第二步加遮挡后的搜索、报告传播、日程恢复；第三步再扩 NPC 个性、救援、更多职业与 AI 台词。

首批验收：
1. 守卫目击砍门必定转向、制止；继续砍会实际接近/出手，不是只扣数。
2. 直接袭击任一在场 NPC 都按能力与性格受击/防卫/逃跑，不因入城剧情免疫。
3. 隔墙听声仅调查；没有见到凶手不精确归责。
4. 河栅无人目击时仍可潜入；不能因任务未触发挡路。
5. 一段连续砍击不重复刷罚款/星数；停止后不无限重复警告。
6. 遮挡后搜索最后位置，不追玩家实时坐标；搜索结束回岗位。
7. 换装不抹除正在目击的身份；提前拿到衣服仍可用于未被识破的交涉。
8. 正在聊天/取水/吃饭也能被危险打断，结束后恢复有效活动。
9. 路径不通要改用呼喊、报信或搜索；不能穿墙、瞬移、永远原地跑。
10. 读档、AI 超时、对白跳过不重结算、不丢案件、不导致人物永久锁死。

开发调试记录：对每次反应保存“事件→感知渠道→已知身份→职责判断→状态切换理由→动作结果”。仅调试面板显示；玩家通过人物动作和少量短句理解世界，不把整套机器状态贴满屏幕。
