# 来访发牌与重复送食（2026-11-11）

连续几天饥饿曾经每天重发同一张送食牌。现在救急和提点共用实际来访、走近、头顶标记、玩家回应、离开流程。

## 规则

- 一轮未缓解的饥饿只发起一次送食。饱食恢复到 45 后才重新允许，且距离上次送食发起至少三个游戏日；拒绝也不会每天重新追着送。收到食物仍不等于吃下，不自动恢复饱食。
- 旧 v2 存档从已有送食牌补录间隔，幂等，不改库存、关系和已结算奖励，不把旧日志猜成某个身份的交谈记忆。
- 认识玩家且没有敌意、已知伤害或亲近者危难的人，可主动带来一条尚未听过的提点。候选来自现有发牌员的真实门路条件，加上已实现的兵刃与吃喝药性话题；无新候选就不来填充闲话。
- 入城门路与普通发牌员共用条件和去重。已持有的物品、已完成的路线、已听过的线索会跳过。只是听到线索不会获得衣服、路引、身份或通行资格。
- 杜老捕等谈动刀及伤亡后果，阿青等谈吃喝里的药性。实际操作提示写成主角无声内心话；不要求 NPC 教人侵害自己。药粉不保证致命，接收不等于食用，仍受距离、遮挡、意愿与察觉规则限制。
- 主动提点点击“询问来意”后直接说具体线索，开场与主题在同一页，不再出现“愿闻其详 / 先不聊 / 暂不回应”确认层，也不先播“可愿听我讲讲”。真正听完且仍可交互才入因果簿与线索记录；Esc、中途换对白、身份变化或走远不提交旧回调。送食、救治仍保留接受、拒绝和暂不回应。
- 来访记忆按说话人和其认出的身份记录。“怎么还在这儿”只用于确有前日关外碰面、目前仍未入城、仍在关外且要谈入城门路的情况。重新打开时复查事实；改脸不继承另一身份的熟识台词。

## DS 的边界

`tools/action_card_lines.py` 是显式执行的两批离线生成，不由游戏启动触发。原始返回、模型、提示词、温度、token 限额和用量保存在 `docs/offline/action-card-lines-2026-11-11.json`；审核修订后的 21 条开场在 `src/action-card-lines.js`。删去了“上次替你治过”“新得消息”等没有证据的前情，也没有生成配音。

每次非寻仇来访开始走近时，调用一次 `/api/director` 的 `action_card` 模式，让 DS 从当次有效的开场和主题中选择。选项包含人物身份、这次看见的需求及该人物对同一面貌的来访记忆，不传全城犯罪日志或秘密身份。无有效 ID 则本地回退；不采用自由生成的奖励、物品或事实。对话已打开、来访被取消或换档后，迟到结果不再覆盖对白。每帧不重复发请求，也不等待网络才显示交互。

本次实际执行两批离线生成和三次浏览器来访选择，使用项目配置的 `deepseek-v4-flash`。运行中的旧 `serve.py` 进程需要重启才能加载新模式；纯静态托管仍可使用本地候选和变化台词。

2026-11-12 根据试玩反馈，将九条提点开场人工改为带 `{topic}` 的直接表达，例如“怎么还在这儿？西边那道河栅泡了十几年，木头早糟了。”开场仍受原有身份与经历条件约束，不默认玩家性别，也不把普通见闻都说成秘密。DS 继续选择有效 ID，本地组合实际台词，不新增网络等待。旧档缓存的询问式开场在重新交互时就地换成直接线索。
