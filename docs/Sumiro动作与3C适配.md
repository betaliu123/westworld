# Sumiro 动作与 3C 本地适配

## 来源与范围

参考试玩：https://xikhar.github.io/sumiro/

动作来源：https://xikhar.github.io/sumiro/assets/player/player.glb

该 GLB 含 43 段骨骼动画。当前保留我们的主角模型，提取动画后重定向到主角骨架，没有把参考项目的地图、任务和控制器直接替换进来。公开 GitHub 仓库查询返回 404，尚未找到明确的资产再分发许可；生成的动画包只用于本地评估，已加入 `.gitignore`。Git 忽略不会阻止其他上传工具打包；发布目录时也应排除此文件，直到确认授权或替换为可分发动作。

## 当前实际接入

- 站立、步行、慢跑、疾跑、持刀站立与移动，根据实际位移速度切换、调整动作速度，动作间淡入淡出。
- 起跳、腾空和落地使用对应动作。世界坐标和跳跃高度仍由现有物理控制，动画不推动角色穿墙。
- 拔刀、收刀、三段普通攻击。每段挥刀只在接触时刻重新检查距离、朝向和遮挡，并结算一次伤害；连续点击最多缓存下一招。
- 受击动作、倒地保持、复活清理。受击、收刀、对话和死亡会取消待命中的攻击。
- 探索镜头拉近，平滑跟随；遇到物理障碍收近，离开后缓慢恢复。点穴/探查保留原模式，增加轻微肩侧偏移。普通对话与剧情镜头仍由原系统管理。

操作不变：WASD 移动、Shift 疾跑、Space 跳跃、/ 拔刀或收刀、左键挥刀、右键拖动镜头、滚轮缩放、Z 蹲行。

蹲行/偷窃、点穴、吃喝、吹笛及乔装继续使用既有程序化动作与道具表演，避免陌生动画覆盖任务接触点。攀爬、攀边、闪避等虽有源动作，本轮未接入玩法，也没有增加对应能力或按键。NPC 骨架未在本轮替换。

## 文件与再生成

- `tools/retarget-motion.py`：读取 GLB，按世界空间休止姿势重定向旋转，处理前向轴与身高比例；保留髋部竖向姿势，移除水平根位移。
- `src/hero-motion.js`：动画混合与状态适配。
- `src/hero-model.js`：模型挂载、骨骼驱动、剑的手部挂点和程序化回退。
- `src/hero-combat.js`：攻击、接招缓存和命中时序；不包含伤害规则。
- `src/orbit-camera.js`：镜头避障与跟随。
- `src/world.js`：接入真实移动、攻击结算、原有互动与镜头。

在项目目录运行（Python 需要 numpy、scipy）：

```powershell
python tools/retarget-motion.py <本地参考player.glb> src/models/hero.glb src/models/sumiro-motion.local.json
```

生成包约 1.57 MB，记录源文件、目标模型 SHA-256 及来源。当前映射针对这两套 Mixamo 骨架；更换模型后需要重新生成和检查朝向，不能把此包当通用动作库。每段动画具有独立 UUID，避免 Three.js 混合器把不同动作当成同一个动作。

可单独打开 `/tests/hero-motion-preview.html` 查看动作，不加载游戏存档。缺少本地动画包时，正式游戏继续使用程序化动作。

- `npm run check` 通过；`npm test` 291 项通过，其中 9 项验证动作切换、接招、打断、死亡恢复及镜头避障。
- 独立浏览器上下文实测城门场景：键盘走跑、跳跃落地、Z 蹲行与恢复、拔刀后连续两击、命中城门耐久、NPC 问责打断、受击、倒地后禁止跳跃。
- 实景检查了贴墙时镜头收近、移动被阻挡时停止跑步、特殊交互结束后恢复动作、复活后解除死亡姿势。
- 浏览器未出现未捕获的运行错误；验证未修改用户原存档。
- 模拟本地动画包缺失（404）后，主角模型仍可见、可移动，程序化回退正常工作。
