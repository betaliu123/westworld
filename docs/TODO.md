## 一、讨论过、尚未开发、文档里也没写

1. **跳过导航废话**
   - 现状："打听正事""还有一事想请教""再聊聊别的"都先让人物说一句"你想打听哪件事？"或"好，你说。"，还要再按一次继续。

   - 位置：`src/talk-tree.js` 中的 `replies` 与 `branch()`；`src/main.js` 的 `topic:more`。

2. **女主角冒用男子路引**
   - 宋代路引写年貌。女主角不着男装冒用"赵成"，几乎必被识破；换上男装后恢复正常判定。
   - 待定：是完全卡死，还是只大幅降低成功率。

3. **物件的意义（认物与来历）**
   - 物件带来历：原主是谁、你怎么得到的（捡到、偷来、受托转交）、当时谁看见。
   - 递交或出示时，先判断这件东西对此人意味着什么：
     - **他的东西，或他正在找**：先认出"这……是我的戒指！"，再问"哪来的？"。回答有三种：
       - 实话：不检定，偷来的要承担后果；
       - 说是捡的：要检定，若当时有目击者，日后会被拆穿；
       - 不解释：他收下，但心存疑虑。
     - **是证据**：按证据处理，例如听雨楼收副账时的"先别惊动他们"。
     - **与他无关**：才走普通送礼。
   - 结算由规则决定，AI 只写措辞（千恩万谢、将信将疑）。
   - 结果记进因果簿，夜里推演长出后续：沈砚告诉苏晚，苏晚次日道谢；若有人亲眼见你偷，就会传出流言。
   - 首批覆盖：银戒、差役服、钱袋、副账。

4. **银戒两个入口结果要一致**
   - 现状：在交谈里说"我把银戒还给你"，会结算沈砚 +6、停止寻找、次日接和好剧情；用"出示/送物"交银戒，只回一句"这份心意我收下了"，归还后果不结算。
   - 要做：两条路走同一套结算。完成第 3 条后自然解决。
   - 位置：`src/main.js` 的送物回调；`src/simulation.js` 中 `intent==='return'` 一段。
