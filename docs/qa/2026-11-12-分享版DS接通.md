# 分享版实时 DS 接通

用户要求开启其他玩家的实时 DS，并明确选择本机临时转发。2026-11-12 已更新原 Drop 展板，访问权限保持不变。

## 实际改动

- 线上基底为 `wuxia-20261112-hud-calligraphy`。上传前核对线上入口、适配器和主模块与该快照一致；新快照 `wuxia-20261112-ds-relay` 的 548 个文件中，仅 `index.html` 和 `drop-static.js` 两个文件变化。
- 实时状态、导演接口和打字意图解析通过专用本机后端与 Cloudflare 临时隧道连接；不开放静态文件和在线语音生成。原有 8091 本地试玩服务不依赖、不重启。
- 服务端密钥仍由本机读取。发布前检查文本资源中不存在实际密钥，发布包不含 `.env`、Python 服务端代码、日志或转发运行状态。
- 启动时曾发现预选端口与旧服务冲突，立即停掉该隧道。已改为系统分配独立空闲端口、禁止地址复用，并在重新连接公网前验证专用服务标识、状态与跨域响应。

## 验证

- `node --test tests/drop-static.test.js`：5 项通过。覆盖原有素材路径、离线回退、三种 AI 请求的转发、取消信号/请求体保留、Cookie 排除和无效地址拒绝。
- `python -m unittest discover -s tests -p test_ds_relay.py -v`：7 项通过。覆盖正确来源、预检、路由/方法限制、文件与语音拒绝、固定后端、敏感请求头不转发、请求校验、限额与断线回退。
- 公网实测状态与 OPTIONS 均为 200，CORS 来源正确；导演请求返回 `action: follow`，约 1.42 秒；打字意图返回 `intent: explain`，约 1.19 秒。记录在 `.artifacts/ds-relay/live-verification.json`。
- 发布后重新下载入口、适配器和主模块，SHA-256 与新快照一致；结果在 `.artifacts/drop/ds-relay-published-verification.json`。
- 浏览器使用 `?playtest=ds-relay-qa` 独立存档。开始游戏后，服务日志成功请求计数从接口探针后的 2 增至 3，确认线上实际调用导演接口；进入守卫交谈并正常显示对白。浏览器错误/警告列表为空。未读写玩家正式存档。

## 边界与停止

这是临时转发，依赖电脑开机联网以及两个后台进程。隧道重启将更换地址，必须重新验证和更新发布入口。请求失败时沿用现有本地回退；没有实现常驻云托管、开机自动启动或账号级配额。转发限制为每小时 300 次、最多 4 并发，仍受底层原有每分钟限制。

停止执行 `powershell -NoProfile -File tools/stop_ds_relay.ps1`，只处理记录且身份吻合的转发进程。原分享链接、规则玩法、存档及已有录音继续保留。
