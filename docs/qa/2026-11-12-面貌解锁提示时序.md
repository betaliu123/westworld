# 面貌解锁提示时序

## 发现与修复

“已结识/已探查”和面貌记录原来由两条路径更新。交谈先写入认识标记并保存，面貌可能等装扮界面每秒的邻近扫描才登记；下一次行动的进度比较就会把先前数人的解锁合并为“可易容面貌 +2”。面貌表按人物 ID 去重，未发现同一青禾在表中被重复增加。

现在每次行动比较进度前同步已结识/已探查的面貌，解锁与原行动一起结算。茶棚旁听先记录两名实际参与者，再保存线索，避免面貌变化留到下一次行动。读档仍先恢复已有知识，再建立进度基线，不补发旧提示。

## 验证

- 修复前新增测试复现：青禾首次交谈结束时没有面貌提示，面貌尚未登记。
- 修复后青禾与符祥先后交谈各新增一次 +1；随后三次扫描和重复交谈不产生额外变化。
- 保存、读档、再次扫描青禾不补报。
- 成功探查立即新增一次面貌，缓存探查与再次扫描不重复。
- 旁听两名新人物当次 +2；同一对人物的下一段旁听不重复。
- `player-floats`、`appearance`、`npc-names`、`progress`、`qinghe`、`world-news` 共 59 项测试通过；修改的运行代码语法检查通过。

本次为逻辑回归，未操作玩家存档。无法由这次描述反推玩家当时的 +2 具体对应哪两个人；修复针对已复现的延迟合并路径。
