# 移动端对白、探索 HUD 与背景音乐 · mobile-experience-1113c

- 纯对白轻点任意画面继续，包括文字区；不再绘制手形继续按钮。关闭按钮优先，回应选项仍须明确选择；长文拖动不翻句，翻句清理其他已按下的手指，避免同次多点触控跳过后续对白。
- 探索不自动绘制日志。江湖菜单中的「记录」打开紧凑、可滚动的历史记录；不会删除存档日志，关闭与 Esc 可退出。
- 气血、体力各为一个 70×4px 的数值条，带不同图标。满值立即隐藏，非满值变化后显示约 4 秒，最后 600ms 淡出。盘缠仍在人物和物品界面查看，不占探索 HUD。
- 当前目标从原有 tracked-quest 读取，恢复左上方至多两行题注；点击打开真实任务入口，6 秒后降低不透明度。与附近冒泡错开，详细面板或对白期间收起。没有增加或修改任务事实。
- 音乐资源没有删除。原 WorldAudio 直接调用 AudioParam.setTargetAtTime / linearRampToValueAtTime；部分微信实现只有 value，会令音乐更新抛错并中断其后的 HUD 更新。增加 value-only 渐变和音量控制，保留支持浏览器自动化方法时的原路径。音频 buffer 自然播放到末尾，不预先调用 stop，避免移动实现的停止时序差异。
- 保留日夜音乐切换、对白压低音乐、吹笛时让出 BGM、统一声音开关、后台停声、回来后正常恢复；没有改配音或调用生成服务。

参考：[微信官方类型定义中的 AudioParam 与 BufferSourceNode](https://github.com/wechat-miniprogram/minigame-api-typings/blob/master/types/wx/lib.wx.api.d.ts)。官方 AudioParam 契约包含 value，没有列出浏览器的自动化方法；以能力检测兼容不同实现，不假定所有手机相同。

验证：85 项自动检查通过，覆盖真实打包 MP3 读取、仅 value 的音量参数、BGM 淡入与下一循环、日夜/吹笛切换、静音/后台，以及对白触控、长文拖动、日志保存和满值隐藏。五档画面 1280×850、1024×768、800×600、844×390、667×375 已做 Canvas 渲染和边界/交叠检查。没有取得 iPhone Air 的现场音频采样；手机声音需重新生成预览后试听。

删掉的常驻内容：手形继续按钮、最近一条日志、气血/体力/金钱数字。新增常驻内容仅当前任务的短题注；状态条按需出现。
