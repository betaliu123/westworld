# 手机性能与清晰度优化 · mobile-perf-1113a

用户设备：iPhone Air；反馈同时有卡顿与动作慢放。本地正式目录与工作副本构建 SHA256 一致，但用户截图仍有已撤下的宽交互条，手机可能在运行旧预览包；需要重新生成预览并扫码，不能只重启旧包。

## 已定位及修复

1. 主循环将每帧推进截为 45ms，20fps 时只推进真实时间的 90%，15fps 为 67.5%，10fps 为 45%。改为按真实间隔推进，单帧最多 125ms，切后台或超过 250ms 的长挂起不追赶。移动按最多 0.18 米的步长逐段检测碰撞，避免低帧率穿过薄墙；挥刀仍只结算一次。
2. 原 HUD 虽然来源是高分辨率画布，最终仍落到场景低分辨率画布。现在场景使用独立 HDR 渲染目标，HUD 在最终原生像素画布合成；色调映射仅在最终场景合成时应用一次。不支持浮点目标的设备退回按场景分辨率直接绘制，保持可运行；这类设备无法独立保留 HUD 最终分辨率。
3. 新安装默认“自动”：场景最多 1.8 倍逻辑像素、150 万像素；HUD 最多 3 倍、400 万像素。保留已有的手动画质选择；自动先降低阴影开销，再试降低场景像素，若帧耗时未改善则恢复清晰度，持续轻载后尝试恢复。高清、均衡、省电仍可切换。通过微信官方 setPreferredFramesPerSecond 请求 60fps，此值不是保证实际达到 60fps。
4. 阴影围绕玩家局部区域绘制，自动档每秒最多刷新 10 次，吃紧时 6 次；原来约每两帧刷新一次。保留人物阴影与原有材质。
5. 邻近人物、交谈/动作目标、追捕者与受击状态立即更新骨骼；中远处骨骼按 15/8Hz 取样并积累真实时间。仅剔除画面外的模型绘制，不停 NPC 行动、感知、事件、物品转移或结算。已淡出的动画层停止求值，恢复动作时重新启用。
6. 无手持物品时不重复求取 NPC 手部世界矩阵；没有手势或混合余量时跳过手势求解与整套骨骼世界矩阵刷新。探索 HUD 画布由每秒 30 次降到 10 次上传，按下/抬起立即刷新，拖动摇杆保持 30Hz。场景人物称呼减弱粗纸色描边与发光，避免糊成白块。
7. 另两个 GLB 重新无损 gzip 压缩，共节约 36,157 字节；模型、贴图与动作原始字节不变。正式入口 game.js、AppID、用户存档未改。

## 验证和限制

- npm run check：75 项通过，包括 60/30/20/15/10fps 的真实时间推进、挥刀单次命中、薄墙碰撞、暂停恢复、远处姿态时间累计、动画层恢复、场景/HUD 像素隔离、自动画质回退、HUD 上传频率及现有启动/交互/资源检查。
- 使用真实 commoner GLB 与原动画片段做 CPU 专项回放：24 个模型（8 个近处、16 个远处），240 帧，三次中位数从 71.81ms 降到 29.10ms，姿态更新从 5,760 次降到 2,400 次。数据只覆盖骨骼更新，不是游戏整帧耗时，更不是 iPhone FPS。
- 微信开发者工具独立存档已进入场景，人物贴图、地面、建筑和 HUD 正常可见，无黑屏或明显曝光错误。本轮没有取得 iPhone Air 的现场性能采样，实际帧率、发热与续航需要手机复测；不声称稳定 60fps。
- 正式主包与资源总量小于 20MiB，精确大小见 dist/build-report.json。启动日志包含 mobile-perf-1113a，可用来辨认新包。
