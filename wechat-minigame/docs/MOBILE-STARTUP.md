# 移动端启动与开场修复（2026-11-13）

版本：`mobile-startup-1113d`。

## 问题与结果

- 正式 `game.js` 原来先下载资源分包，完成后才导入游戏，没有绘制启动画面。现在先运行小型 `dist/boot.js`，用同一 WebGL 屏幕绘制不依赖分包图片/字体的水墨加载页，再下载资源。
- 显示真实下载字节进度、实际完成的人物模型数量；同步引擎准备阶段只显示阶段名称，不伪造百分比。失败或模型长时间无进展保留加载页与重试入口。
- 主包代码尚未获得执行权前的微信平台启动阶段不能由该加载页覆盖；需使用新预览包在真机核对扫码冷启动。
- 原适配层在切换时才创建下一张原生图片，清空 HUD 后异步解码，造成 3D 场景露出。现在提前解码两张开场图；开场始终有不透明底层，下一张未就绪时保留上一张图。开场的显示、揭示第二句、继续、跳过、完成事实仍由原流程控制。
- 模型准备时分次让出事件循环；正式进入菜单前完成首次姿态与场景渲染。首次姿态不从未初始化的绑定姿态混合，不因零帧间隔或远处骨骼降频被跳过。
- 加载期间冻结模拟，未改变存档键或奖励结算。正式入口不启用 QA 存档标志。

## 验证

- 96 项移动端自动检查通过，包括根入口先绘制再下载、真实进度、失败重试、后台 rAF 暂停时的定时器保底、慢图片解码不露场景、五档布局、4 种实际模型的首帧骨骼与贴图检查。
- 浏览器使用实际 `dist/boot.js` 和 `dist/game.js`、原生 WebGL 与图片解码，以微信接口适配测试完整流程：启动首帧 → 下载 → 人物准备 → 欢迎页 → 图一 → 图二 → 探索。29 名 NPC 已加载并建立姿态，错误记录为空，两张开场图均已解码。
- 测试只使用内存中的独立 QA 存档。截图和测试浏览器配置在忽略的 `work/startup-qa/`；未提交或上传玩家存档。
- 自动检查与浏览器截图不能代替 iPhone Air 的微信冷启动、性能和声音实测；需重新编译生成二维码复测。
